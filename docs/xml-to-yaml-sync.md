# XML 修改后同步回 YAML：决策指南

[返回文档总览](README.md) · [三种产物的关系](yaml-xml-html.md)

外部工具可以参与设计编辑，但每次回写完成后，canonical YAML 仍是唯一权威源。本篇帮助维护者判断何时同步、如何审阅风险、遇到问题该停在哪里。

**参数、身份匹配规则、删除授权、报告和回滚的权威操作规范见 [Skill 同步规范](../skills/dec-design/references/xml-yaml-sync.md)。** 该规范的命令从 `skills/dec-design/` 目录执行，输入和输出路径需按实际工程调整；本目录的 [开发与验证手册](development-and-verification.md) 则从仓库根目录执行。

## 1. 先确定要做哪一种变更

| 当前情况 | 选择 |
| --- | --- |
| 只有 XML，尚未建立 canonical YAML | 按 [首次导入规范](../skills/dec-design/references/xml-to-yaml.md) 建立设计源 |
| 已有 YAML，外部工具修改了对应 XML | 按 [同步规范](../skills/dec-design/references/xml-yaml-sync.md) 合并回现有设计 |
| 正在仓库内直接修改业务设计 | 修改 canonical YAML，再派生 XML、HTML 和代码 |
| 希望 YAML 与 XML 各自独立编辑、实时互相覆盖 | 先约定交付版本和回写窗口；当前工具不提供双主协作 |

已有 YAML 时，全量反向导入不能替代同步，否则可能丢失稳定身份和 YAML 独有元数据。准备交给外部编辑的文件，应按 [XML 导出规范](../skills/dec-design/references/yaml-to-xml.md) 保留身份信息，并记录对应的设计版本。

## 2. 收到外部修改后，先保护原件

**先另存外部 XML，再做任何重新生成。** 对已修改的文件先运行 YAML→XML 生成，会用旧设计覆盖尚未回写的内容；为“补身份注释”重新导出也有同样风险。

确认 XML 对应哪份 YAML、从哪个版本导出，以及交付之后仓库是否又改过设计。随后按操作规范预检查，审阅新增、更新和删除是否符合业务意图。报告成功只说明工具完成了相应检查，不能代替人确认这些变化就是想要的变化。

## 3. 常见事故与判断方法

| 场景 | 风险与处理 |
| --- | --- |
| 外部改了规则说明，仓库同期也改了同一字段 | 当前同步没有历史共同基线，不能可靠识别双方修改；对照交付版本、Git 差异和报告，先决定保留哪个业务含义 |
| 外部工具删除身份注释，同时改了名称 | 无法可靠判断改名还是删旧建新；核对原始交付物与节点身份，不要靠放开删除保护消除歧义 |
| XML 少了一个实体 | 先确认是业务删除，还是外部工具漏导出；删除需审阅引用影响，再按规范显式授权 |
| 改名涉及其他文件中的引用 | 身份匹配不等于全项目重构；在隔离分支或完整设计副本中协调变更，再整体校验 |
| 想把候选 YAML 放在原设计目录旁边比较 | 同目录里的同 ID 候选文件会被校验器当成重复定义；用隔离的完整设计副本审阅 |
| 第一个文件同步成功，第二个失败 | 单文件回滚不会撤销前一个文件；检查整个变更集，不能把部分成功当作全项目已同步 |

例如，外部只把“发起支付”改成“发起支付并返回支付信息”，可以审阅这一个描述变化；若同期 YAML 已补充新的支付约束，即使报告没有冲突，也必须核对外部旧内容是否会覆盖这些约束。

## 4. 怎样判断可以继续

预检查通过后，还要确认实际写回的完整设计能够通过目录级校验。涉及跨文件引用的变化尤其如此：预检查成功不代表所有引用有效，更不代表 Runtime 行为已经验证。检查的准确范围和失败处理见 [同步规范](../skills/dec-design/references/xml-yaml-sync.md)。

若出现歧义、校验回滚或异常，保留外部原件、报告与错误输出，先定位问题；不要继续生成覆盖现场。同步报告和 YAML 差异都符合预期，才进入后续验证。

## 5. 回写后的交付

从确认后的 YAML 重新生成受影响的派生产物，并按 [开发与验证手册](development-and-verification.md) 完成目录校验、相关行为测试、漂移与 Binding 证据核对。涉及运行时设计的变更还需重新打包并重建 Runtime，刷新 HTML 不能让运行中的应用自动采用新设计。

交付时说明业务变化、使用的设计版本和实际验证范围。同步成功证明的是受控回写完成；应用行为是否正确，仍由对应的业务测试和集成证据支持。
